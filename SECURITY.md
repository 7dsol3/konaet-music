# Security and supported scope

KONAET Music 2.0 is a prototype using fictional case data. It does not process
real payments or reserve inventory. No production SLA, customer authentication
assessment, independent audit or physical voice/device certification is claimed.

Report sensitive issues using a private repository advisory when enabled.
Do not post customer information, provider keys, checkout links, session cookies
or local state files in public issues. Supply version, reproducible inputs and
expected behavior using synthetic data.

Production model credentials are backend environment variables. Do not share
the official model/provider key with browser code. Native function-calling
schemas, explicit intent guards and deterministic rendering bound model output.
Private order requests bypass the provider. Browser speech recognition may use
the browser vendor's own service, as disclosed in the UI.

Checkout links contain random capability references and reveal only the product
quote until expiry. They are not payment confirmations. Quotes, API responses
and codes are no-store and excluded from service-worker caching. Model text is
rendered as text, not HTML. The same-origin API requires a trusted configured
origin and uses session-owned cart queries.

The SQL state is not encrypted at rest. A single local process and ownership
verification by fixture order/email are not suitable for real customers.
Customer production data requires upstream authentication, deployment review,
durable storage, retention policy and independently enforced limits.

The main-branch policy is configured separately in GitHub. Checks and peer
review are distinct: owner-maintained checks do not demonstrate an independent
security review. The original submitted repository is preserved and is not
modified by releases of this separate product.
